## Session validation regression

The first full run exposed a session latency regression: delta/replay correctness passed, but
plate, turned and NIST commit outliers exceeded the existing 150 ms p90 limit. A genuinely fresh
build of base commit `53aa9f3f` passed the isolated NIST gate at 112.9 ms, confirming that this
batch needed a fix. The separate-target evidence is
`target/rule-pins/session-base-fresh-nist.log`.

Interactive sessions now retain four recently used planning-preparation scopes per thread,
each keyed by the complete Analysis digest, with the complete Spec in each Spec-dependent
candidate key. Preview and commit still invoke the recovered planner; identical candidates and
their pure preparation can be reused. Changed recognition, geometry evidence or PMI invalidate
the scope; Spec changes invalidate their dependent candidates while Analysis-only preparation
can be reused. Ordinary planning and standalone plan-time calibration retain the existing
per-call cache lifetime. There is no new environment bypass,
part-specific branch, threshold change or metric change.

The unchanged eight-test session target passed, with p90 **11.125 ms plate, 10.627 ms dense,
14.657 ms turned and 40.626 ms NIST**. Its existing full fresh-plan, SVG/DXF, annotations,
preview/commit, undo and redo comparisons all remained intact. See
`target/rule-pins/session-analysis-prepared.log`; the cache's input-invalidation pin is
`planning::tests::retained_preparation_binds_the_complete_analysis_and_spec`.

The multi-sheet MCP wall-time gate also fluctuated above 150 ms on an untouched, separately
built base (`multi-sheet-base.log`: p90 699.495 ms; native p90 70.978 ms). The source's atomic
cache writes call `sync_all`; neither durability nor timing assertions were weakened.
